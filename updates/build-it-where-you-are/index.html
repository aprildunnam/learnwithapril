Cowork, Copilot Code or Copilot Studio? Build it where you are.

You can now build apps from three different places in Copilot, and you're not locked into whichever one you start in. Here's how to pick the right starting point, and when to move your idea somewhere bigger.

By April Dunnam·November 19, 2026·10 min read

The big idea

Three front doors, one house

Cowork, Copilot Code and Copilot Studio feel like three separate products. Under the hood, the apps they build all run on Copilot Managed Runtime, Microsoft's hosting inside your Microsoft 365 environment. Every app built there runs in a Microsoft-hosted environment, signs people in with Microsoft Entra and follows your tenant's governance.

Apps are also versioned in Git, and an app you start in Cowork can be opened and edited in Copilot Studio. So picking a starting point is a low-stakes choice. Start where you're comfortable, and move up when the idea grows. It even works for apps built outside Microsoft, like Lovable. See how it works.

My analogy

Cowork is the sticky note. Copilot Code is the workbench. Copilot Studio is the production line. They're all in the same building with the same security guard at the door, so you can carry your work from one room to the next.

Under the hood

How Copilot Managed Runtime works

This is the layer that makes "build it where you are" true. It's an IT-governed platform for running code inside your Microsoft 365 tenant, and it doesn't care which tool built the app. Here's where your app lives, how changes reach people, and who controls what.

Where your app is stored

The code lives in a Git repository, the single source of truth, and every build traces back to a real commit. By default the platform manages that repo for you. Developers building with the CLI can bring their own repo instead, as long as it belongs to a GitHub Enterprise Cloud organization. You pick when the app is created and can't switch later.

How changes reach people

You can preview any commit or branch, and nothing goes live until you deploy. The live app keeps running while you keep working. If a build fails, the old version stays up. To roll back, deploy an older commit. Nothing is lost.

Who controls what

Building in Cowork is on by default, and admins can limit it to specific people. Copilot Code is managed through spending policies. Copilot Studio has its own tenant setting, and the CLI and SDK are off by default. Running an app needs a Power Apps Premium license or Copilot Credits.

Already building in Lovable?

Bring it inside your tenant

This is the surprise in the runtime story. Lovable apps can publish straight into Copilot Managed Runtime. People open them with their work login, IT manages them like any other Microsoft app, and they show up in the same admin inventory. That gives the vibe-coded apps already floating around your company a governed home.

  • Lovable plan: Lovable says it needs a Business or Enterprise plan, and it's rolling out gradually.
  • One-time admin setup: consent to the Lovable app in Microsoft Entra, then allow CLI app creation and external artifact deployment in the environments you approve.
  • Where things live: the published app runs in your tenant, but the Lovable project source and chat history stay in Lovable.
  • Worth knowing: no public or anonymous access, publishing is tied to the identity that owns the Lovable connection, and deleting the Lovable project doesn't delete the live app.

Start to finish

One idea, three stops

Here's how an idea grows at April's Acoustic Cafe, the fictional cafe and music shop I use in SkillUp. Maya runs events and is drowning in performer sign-ups.

  1. Week 1 · Cowork

    Maya types /app in Cowork: "Build me a tracker for open mic sign-ups from my inbox, with name, instrument, preferred date and status." She's using it the same afternoon.

  2. Week 3 · Copilot Studio

    The whole events team wants it, and performers keep asking about their slot. Maya opens the app in Copilot Studio, adds an agent that answers "When am I on?" and a workflow that sends a reminder two days before each show.

  3. Month 3 · Copilot Code or a developer

    The cafe wants it to take ticket payments and show a public schedule. That's real software now, so a developer takes it from there, building on the app's history instead of starting over.

Why it matters

Maya didn't need a requirements doc to start, and nobody threw away her work to scale it. That's the shift. The person closest to the problem builds the first version, and it grows from there.

When to move up

Five signs your idea has outgrown where it started

  • People outside your team are asking for access. That's when sharing, permissions and support start to matter.
  • It needs to do things on its own. Reminders, follow-ups and answering questions are agent and workflow work. That's Copilot Studio.
  • It needs approvals or touches several systems. Business processes belong where you can see and govern every step.
  • More than one person needs to change it. Move it to Copilot Studio's co-authoring, or to a Git repo a developer owns.
  • Someone asks, "What happens if you're out sick?" If the answer is "it breaks," it needs an owner and a home that isn't your chat history.

My rule of thumb

Build in the smallest tool that does the job, and move up the moment the job changes. Starting big slows you down. Staying small too long leaves your team depending on one person's side project.

Before you start

Notes for your team

  • Check what's turned on. Cowork app building and Copilot Code started in the Frontier program. Your admin controls who gets each, so ask before you plan around one.
  • Know how it's billed. Cowork, Code and Autopilot use usage-based billing. Chat and Copilot across Microsoft 365 stay covered by the user license. Ask IT how Copilot Credits work in your org.
  • Data access follows your rules. Apps use the connectors your admins allow and your existing permissions. Nobody gets data they couldn't already see.
  • Test before you share. Preview it, try it with real data, and have one other person break it before it goes to the whole team.

For admins

Decide now who can build where, and what "ready to share company-wide" means. Makers will start in Cowork whether or not you have a plan. A clear path to Copilot Studio is what keeps those apps from turning into shadow IT.
