Five places an app can live

Think of it like choosing where a business sets up shop. Each option suits a different kind of tenant, and the rent works differently too.

Who pays to run it

The licensing difference nobody's talking about

For a lot of teams this decides it. A canvas app that only uses standard connectors, like SharePoint, runs on the Power Apps rights included with most Microsoft 365 plans. The same app on Copilot Managed Runtime doesn't. Microsoft's docs are clear that those included rights don't cover Copilot Managed Runtime, whatever connector it uses.

User hasCanvas app, standard connectorsCopilot Managed Runtime app
Microsoft 365 E3 or E5Runs itNeeds a spending policy
Power Apps PremiumRuns itRuns it, no credits for normal use

The good news

Runtime credits are cheap for light use. It's 0.1 Copilot Credits per API call, and Microsoft suggests a starting limit of 100 credits, about US$1, per user per month, which typically covers several hundred launches.

Admins, set this up first

Create one spending policy for all users that includes Copilot Managed Runtime, before apps get shared. Premium users can stay in it, because their license is used first. A Microsoft 365 Copilot license doesn't cover runtime on its own.

Code apps vs Managed Runtime

The two that look the same

Power Apps code apps and Copilot Managed Runtime apps are both code-first web apps with Entra sign-in, 1,500+ connectors, and your DLP and Conditional Access policies. The difference is where they live and who manages them.

 Code appsManaged Runtime
Lives inA Power Platform environmentCopilot Managed Runtime, with Git as the source of truth
Managed inPower Platform admin centerMicrosoft 365 admin center
Built withPower Apps CLI and the client libraryCowork, Copilot Code, Copilot Studio, the ms CLI, or Lovable
Users run it withPower Apps Premium, pay-as-you-go or App PassPower Apps Premium or Copilot Credits

My take

If your team already runs on Power Platform environments, solutions and pipelines, code apps fit what you have. If the app started as a conversation in Copilot, or you want per-use billing for light users, Managed Runtime is the natural home.

Rules of thumb

When I'd still reach for Power Apps

  1. It already works

    Don't rebuild a working app to chase the new thing. Turn on Copilot in it and let agents use its data instead.

  2. Your users only have Microsoft 365

    A canvas app on SharePoint costs nothing extra to run. That's hard to beat for a team tool.

  3. It's record-heavy and process-heavy

    Related tables, security roles, stages and auditing are what model-driven apps on Dataverse were made for.

  4. It's used on phones in the field

    Canvas apps in the Power Apps mobile app, with offline support, are a proven route for frontline work.

  5. People outside the company use it

    That's a Power Pages job.

And when I'd reach for Managed Runtime

When someone can describe the app faster than they could build it, when it started in Cowork, Copilot Code or Copilot Studio, or when a pro dev or Lovable is building it and wants Git, previews and rollback with Microsoft 365 governance.

They work together

Your Dataverse tables and Power Platform connectors don't care which kind of app calls them. A Managed Runtime app can sit on the same data your model-driven app uses.
