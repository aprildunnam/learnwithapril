DECISION TOOL · POWER APPS

Power Apps or Copilot Managed Runtime? Pick the right home for your app.

Copilot Managed Runtime runs anything a modern web app can do, from a tracker to an interactive 3D model, with Microsoft hosting and governing it. Power Apps still wins plenty of jobs too. Here's where each one runs, how it's managed, what it's great at, where it falls short, and a picker to help you choose.

The big picture

It's a spectrum, not a replacement

Microsoft's own docs put these on a line from opinionated to open. Think of it like housing. Power Apps is a furnished apartment: walls, plumbing and furniture included, you just arrange it. Copilot Managed Runtime is a custom home on a managed lot: you design anything you like, and the HOA handles security and utilities. Azure is raw land.

Most built for you

Canvas and model-driven apps

Power Fx, drag-and-drop or generated screens, Dataverse forms and views. Fastest for makers, with guardrails baked into the model.

Code on Power Platform

Code apps

Your React or Vue code, running inside a Power Platform environment with its connectors and policies.

Open code, managed host

Copilot Managed Runtime

An open-standard web app built from a conversation or a repo. Microsoft runs the host, identity, policy and monitoring.

All on you

Azure custom apps

Any framework and service. Your team owns hosting, security, monitoring and deployments.

Power Pages sits beside this line. It's the option for people outside your organization.

What CMR unlocks

If a browser can do it, your app can too

This is the part people underestimate. A Copilot Managed Runtime app is a full single-page web app, so you're not limited to the controls a designer gives you. In one of my labs this week, someone built an interactive 3D model. That's not a canvas app job.

  • Any UI

    Any framework or library you can bundle: 3D and WebGL, maps, rich charts, drag-and-drop boards, animation, canvas drawing. The runtime doesn't impose conventions on your code beyond the SDK.

  • Agentic

    Built for agents. The default policy includes 12 Microsoft MCP servers, like Work IQ for mail, calendar, Teams and SharePoint, and the Power Apps MCP Server, so apps can reason over work context.

  • Real ALM

    Git behind every version. Preview any commit, deploy when you're ready, roll back to an earlier commit, or bring your own GitHub Enterprise Cloud repo.

  • Preview

    A database when you need one. Fabric can provide a relational backend for app data, with the schema defined in code.

  • Any builder

    Build from anywhere: Cowork, Copilot Code, Copilot Studio, the ms CLI with your coding agent, or Lovable. Everything lands in one governed place.

Why it matters

For years, the answer to "can Power Apps do this?" was sometimes "not without a PCF control and a developer." With Copilot Managed Runtime, a business user can describe something ambitious and get a real web app that IT can still see and govern.

Know this before you build something fancy

The default security policy only loads scripts, fonts and data from the app itself, and turns web workers off. Bundle your libraries into the app instead of pulling them from a CDN. If you truly need an outside source or a web worker, your admin can allow that specific one.

Strengths and watch-outs

What each one is great at, and where it bites

Power Apps

Canvas apps

A blank storefront you lay out yourself.

Strengths

  • Runs on Microsoft 365 licenses with standard connectors
  • Works in Teams, SharePoint and Power BI
  • Mobile app with offline support
  • Huge maker community and know-how

Watch-outs

  • Delegation limits on large data
  • UI is limited to the controls you have, unless someone builds a PCF component
  • Copilot in canvas apps is still preview, with limits

Power Apps

Model-driven apps

An office building with the filing system already installed.

Strengths

  • Security roles, business process flows and auditing built in
  • Microsoft Copilot in the app is GA
  • Its data becomes context for agents through Work IQ

Watch-outs

  • Needs Power Apps Premium and Dataverse
  • Looks and feels like a business app, by design
  • Copilot in the app also needs a Microsoft 365 Copilot license

Power Apps

Code apps

A custom-built shop on Power Platform land.

Strengths

  • Full UI control in React or Vue
  • Fits teams already running Power Platform environments, solutions and DLP
  • Alerting and metrics in Power Platform monitor

Watch-outs

  • Needs a developer to build and maintain it
  • Users need Power Apps Premium, pay-as-you-go or an App Pass
  • Overlaps heavily with Copilot Managed Runtime

Power Pages

Power Pages sites

The storefront window people outside the company walk up to.

Strengths

  • The only option here built for external users
  • Sign-in or anonymous access, with table permissions on Dataverse

Watch-outs

  • Licensed by site capacity, so plan for traffic
  • Overkill for an internal team tool

New at Ignite

Copilot Managed Runtime

A custom home on a managed lot.

Strengths

  • No UI ceiling: 3D, maps, animation, anything a web app can do
  • Anyone can build it by describing it, then a developer can take it further from the same repo
  • Work IQ and MCP servers built into the default policy
  • Git, previews and rollback for every app
  • One inventory, health monitoring and blocking in the Microsoft 365 admin center
  • Pay-per-use credits for light users

Watch-outs

  • Microsoft 365 E3 or E5 alone doesn't cover running it
  • No offline, and no documented Teams or SharePoint embedding yet
  • Guests can't open apps yet
  • Only 19 connectors allowed by default, so third-party and custom ones need an admin
  • Spending can't be scoped to a single app

Who pays to run it

The licensing difference nobody's talking about

For a lot of teams this decides it. A canvas app that only uses standard connectors, like SharePoint, runs on the Power Apps rights included with most Microsoft 365 plans. The same app on Copilot Managed Runtime doesn't. Microsoft's docs say those included rights don't cover Copilot Managed Runtime, whatever connector it uses.

User hasCanvas app, standard connectorsCopilot Managed Runtime app
Microsoft 365 E3 or E5Runs itNeeds a spending policy
Power Apps PremiumRuns itRuns it, no credits for normal use

The good news

Runtime credits are cheap for light use. It's 0.1 Copilot Credits per API call, and Microsoft suggests a starting limit of 100 credits, about US$1, per user per month, which typically covers several hundred launches.

Admins, set this up first

Create one spending policy for all users that includes Copilot Managed Runtime, before apps get shared. Premium users can stay in it, because their license is used first. A Microsoft 365 Copilot license doesn't cover runtime on its own.

Rules of thumb

When I'd still reach for Power Apps

  1. It already works

    Don't rebuild a working app to chase the new thing. Turn on Copilot in it and let agents use its data instead.

  2. It lives in Teams or SharePoint

    Canvas apps embed in Teams tabs, SharePoint pages and list forms today.

  3. It's used on phones in the field

    The Power Apps mobile app, with offline support, is the proven route for frontline work.

  4. It's record-heavy and process-heavy

    Security roles, stages and auditing are what model-driven apps on Dataverse were made for.

  5. People outside the company use it

    That's a Power Pages job.

When I'd reach for Managed Runtime

  • The idea is bigger than a canvas: 3D, maps, interactive visuals or a custom design
  • Someone can describe it faster than they could build it
  • It should work with Copilot, agents and Work IQ from day one
  • You want Git, previews and rollback without running hosting yourself
  • A developer or Lovable is building it, and IT wants it in the Microsoft 365 inventory
They work together

Your Dataverse tables and connectors don't care which kind of app calls them. A Managed Runtime app can sit on the same data your model-driven app uses.
